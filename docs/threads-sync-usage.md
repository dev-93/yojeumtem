# Threads 수집 실행

별도 프론트 화면 없이 TypeScript 배치가 실행되고, Threads 결과는 기존 통합 콘텐츠 DB에 표시됩니다.

## 실행 환경

Node 22.17 이상을 사용합니다. 현재 Mac에 설치된 버전으로 전환하려면:

```sh
export PATH="$HOME/.nvm/versions/node/v22.17.1/bin:$PATH"
node --version
```

실행과 테스트에는 외부 패키지가 필요하지 않습니다. `npm install`은 정적 타입 검사 도구를 설치할 때 필요합니다.

## 인증 준비

1. Meta 개발자 앱에서 본인 Threads 계정에 `threads_basic`, `threads_manage_insights` 읽기 권한을 부여한 사용자 토큰을 발급합니다. 계정 ID도 확인합니다.
2. Notion 내부 통합을 생성하고 요즘템 부모 페이지에 읽기·삽입·수정 권한을 연결합니다. ChatGPT에 연결된 Notion 인증이 이 프로그램에 자동 전달되지는 않습니다.
3. `.env.threads-sync`에 값을 로컬에서 입력합니다. 기존 설정이 있으면 보존합니다. 인증값을 채팅이나 Git에 올리지 않습니다. 예시 파일은 제거했습니다.

```sh
export THREADS_SYNC_ENV_FILE="$PWD/.env.threads-sync"
npm run identify # 사용자 ID 조회 후 같은 설정 파일에 저장
npm run doctor
```

## 기존 콘텐츠 DB 연결과 수집

```sh
npm run setup
```

콘텐츠 DB는 Notion에서 이미 확장해 사용 중이므로 새 DB를 생성하거나 초기화하지 않습니다. 기존 `NOTION_DATA_SOURCE_ID`와 `NOTION_SUMMARY_BLOCK_ID`를 그대로 유지합니다. `setup`은 설정된 Data Source를 확인하고, ID가 설정되지 않은 경우 `Threads 게시글` 또는 `콘텐츠 DB`라는 기존 하위 DB가 있는지 확인해 새 DB를 만들지 않고 중단합니다. 기존 ID를 준비한 뒤 전용 설정 파일에 유지/입력합니다. 요약 블록은 선택 항목입니다.

```sh
npm run sync -- --dry-run
npm run sync -- --full
npm run sync
```

`--dry-run`은 Threads 읽기를 검증하며 Notion 게시글을 생성/수정하지 않습니다. 실수 방지를 위해 DB 설정은 필요합니다. 원문은 로그에 출력하지 않습니다.

전체 수집은 처음 또는 마지막 전체 수집 후 7일이 지난 경우 실행됩니다. 이후 수집은 최근 14일과 마지막 성공 이후 구간을 겹쳐 조회합니다. 기존 Notion 행은 `Threads ID`로 찾아 갱신해 중복 생성을 방지합니다. 신규/갱신 행의 `채널`은 `Threads`로 설정하며 조회수·좋아요·댓글 등 성과를 계속 갱신합니다. 제휴링크 Relation, 제작 방식 등 수집기가 관리하지 않는 속성은 업데이트 payload에서 제외해 기존 값을 보존합니다. 리포스트는 신규 수집·갱신 대상에서 제외하며 기존 리포스트 행은 삭제하지 않습니다. 인스타 릴스·네이버 클립·네이버 블로그는 자동 수집하지 않습니다. `THREADS_SOURCE` 전용 블록에는 JSON 전체 대신 게시물 텍스트만 기록합니다. 기존 JSON 블록도 다음 정상 동기화 때 텍스트로 바뀝니다.

## 검증

```sh
npm test
npm install
npm run check
```

인증 후 실제 글 3~5개를 화면과 비교하고, 처음에는 `npm run sync -- --dry-run`으로 API 읽기/리포스트 제외 수를 확인합니다. 실제 쓰기는 운영 DB에 영향을 주므로 승인된 배포 절차에서 검증합니다. `Threads ID` Upsert로 같은 수집을 반복해도 중복 행이 생기지 않아야 합니다. 이미지·영상 자체의 의미는 수집기가 해석하지 않습니다.

## 운영 제약

- 정기 배포·예약과 장기 토큰 자동 갱신은 아직 구현하지 않았습니다. 토큰 만료 시 재인증이 필요합니다.
- 수집 상태는 `.runtime/threads-sync/`에 보존합니다. 동시 실행 방지는 같은 작업 폴더에서만 유효하므로 배포 시 단일 실행을 보장해야 합니다.
- 비정상 종료로 잠금이 남으면 실제 실행이 없는지 확인한 뒤 해당 `lock` 파일만 제거합니다.
- 초기 게시글이 1,000개를 넘으면 저장 전 중단합니다. 기간 분할·이어받기는 후속 구현입니다.
- 댓글 원문·성과 시계열·인사이트 추천은 포함하지 않습니다. Notion에는 최신 누적 지표만 저장합니다.
- API 인증·실제 저장을 확인하기 전에는 정기 수집을 운영 중이라고 판단하지 않습니다.

## 간소화한 DB 속성

계정 ID·유형·원문 구분·본문 확인 시각은 표 속성에서 제거했습니다. 원문 전용 블록에는 게시물 텍스트만 보존하며, 미디어/인용 메타데이터는 기록하지 않습니다. 성과 관측 시각은 마지막 수집으로 이름을 바꾸었으며 성과 조회 성공 시에만 갱신합니다. 수집 상태는 Status로 정상/일부 지표 미확인을 사용합니다. Threads ID는 중복 방지에 필요하므로 속성 자체는 유지합니다.

통합 콘텐츠 DB의 채널 Select는 `Threads` 값으로 설정됩니다. `doctor`는 수집에 필요한 기존 성과 속성과 `채널`, `제휴링크`, `제작 방식`, `정보태그 조회`, `영상 길이(초)`의 존재/타입 및 `Threads` 옵션을 확인합니다. 콘텐츠 DB 이름은 API 동기화에 사용되지 않으며, Railway의 환경변수, Data Source ID, Cron, Volume 상태 경로와 실행 잠금은 변경하지 않습니다.
